# نظام النقل الوظيفي الإلكتروني — المؤسسة العامة للري

نموذج أولي (Prototype) لنظام إلكتروني يدير طلبات نقل الموظفين من لحظة تقديم الطلب حتى تنفيذ القرار الإداري، مع دعم عدة طلبات في آن واحد وتبديل الأدوار لمحاكاة كل طرف في المسار.

## المزايا

- صفحة رئيسية بثلاثة خيارات: تقديم طلب ومتابعة طلباتي، والدخول كموظف بقسم تخطيط الموارد البشرية (رئيس القسم أو مسؤول التخطيط)، والاطلاع على طلبات الموافقة حسب دور المستخدم.
- لوحة طلبات تعرض الموظف ومسؤول التخطيط المكلَّف وحالة كل طلب، وتُبرز الطلبات التي ينتظر فيها دور المستخدم الحالي.
- ثلاث صفات لمقدّم الطلب: الموظف نفسه (تُعبّأ بياناته تلقائيًا)، أو مدير قسم ينقل موظفًا من قسمه، أو مدير قسم ينقل موظفًا إلى قسمه.
- اختيار الموظف من قائمة الأرقام الوظيفية مع البحث بالرقم أو الاسم، وتعبئة بياناته تلقائيًا (تمثيل للربط مع نظام بيانات الموظفين).
- البحث في لوحة الطلبات بالرقم الوظيفي أو اسم الموظف.
- نقل أكثر من موظف في طلب واحد عبر جدول يقبل اللصق المباشر من Excel.
- موافقة مدير قسم الموظف الحالي و/أو مدير قسم الموظف الجديد بعد تقديم الطلب مباشرة، حسب صفة مقدّم الطلب.
- رئيس قسم تخطيط الموارد البشرية يستقبل الطلبات ويسندها لأحد مسؤولي التخطيط الخمسة؛ المسؤول المكلَّف وحده يتخذ الإجراءات، والبقية يطّلعون فقط.
- إرسال الطلب للموظف لأخذ موافقته (اختياري)، مع ملخص للبدلات المفقودة والمنطقة والمهام الجديدة، ودون إظهار ملف المعاملة له.
- سلسلة اعتماد (النائب ← مدير التخطيط ← مدير الموارد البشرية ← رئيس المؤسسة)، ومسار مستقل لاعتماد رفض مسؤول التخطيط.
- قرار إداري في صفحة واحدة (النص والجدول) يُعبّأ تلقائيًا بأسماء الموظفين وبياناتهم، مع زر للطباعة.
- بطاقة "الإجراء الحالي" ملوّنة عندما يكون على المستخدم إجراء، ورصاصية عندما لا يكون.
- واجهة عربية (RTL) متجاوبة مع الجوال وتدعم الوضع الداكن.

## هيكل المشروع

```
sio_staff_transfer/
├── index.html                  # الصفحة الرئيسية (الهيكل ونافذة السياسات)
├── assets/
│   ├── css/
│   │   └── main.css            # الأنماط والألوان (هوية المؤسسة + الوضع الداكن)
│   ├── images/
│   │   └── logo.png            # شعار المؤسسة
│   └── js/
│       ├── config/
│       │   ├── roles.js        # الأدوار ومسؤولو التخطيط وألوان المراحل
│       │   ├── employees.js    # بيانات الموظفين التجريبية وإعدادات القرار الإداري
│       │   └── form-schemas.js # مخطط النماذج والمسار لكل خطوة
│       ├── core/
│       │   ├── state.js        # حالة الطلبات وإنشاؤها واختيارها
│       │   ├── fields.js       # التحقق من الحقول وتحديث البيانات
│       │   └── workflow.js     # الانتقال بين الخطوات والقرارات
│       ├── ui/
│       │   ├── policy-modal.js # نافذة سياسات النقل
│       │   ├── decision-sheet.js # ورقة القرار الإداري وطباعتها
│       │   ├── portal.js       # الصفحة الرئيسية وبوابات الدخول
│       │   └── render.js       # رسم اللوحة والنماذج وملف المعاملة
│       └── app.js              # نقطة التشغيل
└── docs/
    └── workflow.md             # توثيق مسار الطلب ومراحله
```

الملفات عبارة عن سكربتات عادية (بدون أدوات بناء) تُحمَّل بالترتيب الوارد في `index.html`، لذا يجب الحفاظ على هذا الترتيب عند إضافة ملفات جديدة.

## التشغيل

لا يحتاج النظام إلى خادم أو تثبيت أي حزم:

- افتح `index.html` مباشرة في المتصفح، **أو**
- شغّل خادمًا محليًا بسيطًا من مجلد المشروع:

```bash
python3 -m http.server 8000
# ثم افتح http://localhost:8000
```

## التخصيص

- **إضافة حقل أو تعديله:** عدّل المصفوفة `fields` داخل الخطوة المطلوبة في `assets/js/config/form-schemas.js`. الأنواع المدعومة: `text`، `date`، `textarea`، `select`، `radio`، `checkbox`، `checkbox-single`، `employee-picker`، `employee-table`. ويمكن إظهار حقل أو قسم بشرط عبر `showIf`.
- **بيانات الموظفين ونص القرار الإداري:** في `assets/js/config/employees.js` (البيانات الحالية تجريبية وتُستبدل بالربط مع نظام الموظفين).
- **تعديل المسار:** غيّر قيمة `next` أو دالة `route` أو مصفوفة `decisions` في الخطوة نفسها.
- **إضافة دور:** أضفه إلى `ROLES` في `assets/js/config/roles.js` واستخدم الاسم نفسه في `actor` للخطوة.
- **الألوان والهوية:** المتغيرات في أعلى `assets/css/main.css`.

## ملاحظات

- هذا نموذج أولي: البيانات محفوظة في ذاكرة المتصفح فقط وتُفقد عند تحديث الصفحة، وبيانات الموظفين تجريبية، وورقة القرار تحمل علامة "نسخة تجريبية".
- للانتقال إلى نظام إنتاجي يلزم ربطه بخادم وقاعدة بيانات ونظام صلاحيات وتسجيل دخول.

مسار الطلب بالتفصيل موثّق في [docs/workflow.md](docs/workflow.md).
