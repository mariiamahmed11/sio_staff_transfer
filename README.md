# نظام النقل الوظيفي الإلكتروني — المؤسسة العامة للري

نموذج أولي (Prototype) لنظام إلكتروني يدير طلبات نقل الموظفين من لحظة تقديم الطلب حتى تنفيذ القرار الإداري، مع دعم عدة طلبات في آن واحد وتبديل الأدوار لمحاكاة كل طرف في المسار.

## المزايا

- لوحة طلبات تعرض حالة كل طلب والجهة المسند إليها، وتُبرز الطلبات التي ينتظر فيها دور المستخدم الحالي.
- محاكاة ثمانية أدوار: مقدم الطلب، مسؤول تخطيط الموارد البشرية، مسؤول الموافقات المالية، الموظف المطلوب نقله، وسلسلة الاعتماد الإداري (نائب مدير التخطيط ← مدير التخطيط ← مدير الموارد البشرية ← رئيس المؤسسة).
- نافذة سياسات النقل الوظيفي تُشترط الموافقة عليها قبل تعبئة الطلب.
- نماذج ديناميكية مبنية من مخطط واحد (`FORM_SCHEMAS`) مع التحقق من الحقول الإلزامية.
- توجيه آلي: يمر الطلب على مسؤول الموافقات المالية فقط عند وجود أثر مالي.
- قرارات الاعتماد / الرفض / الإرجاع للتعديل، مع إلزامية الملاحظة عند الرفض أو الإرجاع.
- ملف معاملة يحفظ لقطة من بيانات كل خطوة، وسجل زمني للإجراءات.
- واجهة عربية (RTL) متجاوبة مع الجوال وتدعم الوضع الداكن.

## هيكل المشروع

```
sio_staff_transfer/
├── index.html                  # الصفحة الرئيسية (الهيكل ونافذة السياسات)
├── assets/
│   ├── css/
│   │   └── main.css            # الأنماط والألوان (هوية المؤسسة + الوضع الداكن)
│   ├── images/
│   │   └── logo.png            # شعار المؤسسة
│   └── js/
│       ├── config/
│       │   ├── roles.js        # الأدوار وألوان المراحل
│       │   └── form-schemas.js # مخطط النماذج والمسار لكل خطوة
│       ├── core/
│       │   ├── state.js        # حالة الطلبات وإنشاؤها واختيارها
│       │   ├── fields.js       # التحقق من الحقول وتحديث البيانات
│       │   └── workflow.js     # الانتقال بين الخطوات والقرارات
│       ├── ui/
│       │   ├── policy-modal.js # نافذة سياسات النقل
│       │   └── render.js       # رسم اللوحة والنماذج وملف المعاملة
│       └── app.js              # نقطة التشغيل
└── docs/
    └── workflow.md             # توثيق مسار الطلب ومراحله
```

الملفات عبارة عن سكربتات عادية (بدون أدوات بناء) تُحمَّل بالترتيب الوارد في `index.html`، لذا يجب الحفاظ على هذا الترتيب عند إضافة ملفات جديدة.

## التشغيل

لا يحتاج النظام إلى خادم أو تثبيت أي حزم:

- افتح `index.html` مباشرة في المتصفح، **أو**
- شغّل خادمًا محليًا بسيطًا من مجلد المشروع:

```bash
python3 -m http.server 8000
# ثم افتح http://localhost:8000
```

## التخصيص

- **إضافة حقل أو تعديله:** عدّل المصفوفة `fields` داخل الخطوة المطلوبة في `assets/js/config/form-schemas.js`. الأنواع المدعومة: `text`، `date`، `textarea`، `select`، `radio`، `checkbox`، `checkbox-single`، `file`.
- **تعديل المسار:** غيّر قيمة `next` أو دالة `route` أو مصفوفة `decisions` في الخطوة نفسها.
- **إضافة دور:** أضفه إلى `ROLES` في `assets/js/config/roles.js` واستخدم الاسم نفسه في `actor` للخطوة.
- **الألوان والهوية:** المتغيرات في أعلى `assets/css/main.css`.

## ملاحظات

- هذا نموذج أولي: البيانات محفوظة في ذاكرة المتصفح فقط وتُفقد عند تحديث الصفحة، والملفات المرفوعة يُحفظ اسمها وحجمها فقط.
- للانتقال إلى نظام إنتاجي يلزم ربطه بخادم وقاعدة بيانات ونظام صلاحيات وتسجيل دخول.

مسار الطلب بالتفصيل موثّق في [docs/workflow.md](docs/workflow.md).
